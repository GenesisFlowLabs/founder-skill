# founder-brand

Resolve this loaded skill directory with `pwd -P`, set `SKILL_DIR` and parent `PACK_DIR`, and read `"$PACK_DIR/founder/policy.md"` plus the relevant `profiles.md` section. Use the authorized `RUN` workspace.

1. Read current brand assets, approved name, buyer evidence, positioning and product claims. Preserve existing company/product names and identifiers. Naming is optional and occurs only when the user requests it or the project is explicitly unnamed.
2. State the intended customer impression, supported promise and voice in plain language. Provide a brief before/after rewrite of an existing draft using only claims the current sources support.
3. Brief the look: a small palette with hex values and checked text contrast, typefaces with current license/source, logo usage and the relevant touchpoints. For B2B this may mean a proposal, onboarding view, operational screen and support reply. Reuse licensed existing assets before proposing replacements.
4. If naming is in scope, offer a small candidate set. Research current official trademark registers, domains and relevant handles. Report exact searches, market/class, observation date and unresolved results. Availability searches do not establish legal clearance or registration.
5. Label generated visual ideas as concepts. Do not imply that a brief is a finished identity or that a proposed capability/benefit is already delivered.

Return the retained identity, voice examples, visual brief, evidence/licensing limits and one next action in the requested format; use `brand.md` only if a separate artifact is needed. Use US spelling including color and license. Do not copy a competitor's identity, manufacture endorsements or launch public profiles as part of creating the brief.
