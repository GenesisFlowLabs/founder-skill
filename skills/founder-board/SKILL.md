# founder-board

Resolve the directory containing this loaded `SKILL.md` with `pwd -P`, set `SKILL_DIR` to it and `PACK_DIR` to its parent. Read `"$PACK_DIR/founder/policy.md"` and the relevant `profiles.md` section. `RUN` is the authorized workspace defined there.

1. Read the existing brief, project instructions and current evidence. Reuse `idea.md` if present; otherwise summarize the known buyer, workflow, outcome, proposed terms and constraints in the requested output. Create `idea.md` only if needed by a selected downstream workflow. Mark missing price, name or budget unknown, and continue useful analysis.
2. Read `"$SKILL_DIR/lenses.md"`. Apply Offers, Monopoly and Product as published framework summaries. Do not impersonate their authors, quote unsourced words or imply endorsement. Default to three short inline sections. Separate memos or sequential agents are optional when useful; respect the shared limit of two concurrent agents.
3. For each lens state the strongest supported case, the critical risk, evidence needed, and PROCEED / PROCEED IF / HOLD. These are judgments, not investment commitments. Avoid numerical scores without a defined rubric.
4. Return the recommendation, common risks, genuine disagreements, conditions and one next action with owner in the requested format. Use `board.md` only when a separate artifact is needed. Link to source records rather than duplicating private briefs.

Choose the next specialist from the actual unresolved decision. Use real buyer interviews for demand questions; a panel is optional objection research. Do not turn a board opinion into proof of demand or projected profitability.
